# 🔒 Security Policy

Thank you for helping keep **Quantiva-AI** secure.

We take the security of our users and contributors seriously. If you discover a security vulnerability, please report it responsibly.

---

# Supported Versions

| Version | Supported |
|----------|-----------|
| Latest (main) | ✅ |
| Previous Stable | ✅ |
| Older Versions | ❌ |

---

# Reporting a Vulnerability

If you believe you have found a security issue, **please do not open a public GitHub Issue**.

Instead:

- 📧 Contact the maintainers privately.
- Include detailed steps to reproduce the issue.
- Attach screenshots, logs, or proof-of-concept code if applicable.
- Allow us reasonable time to investigate before public disclosure.

---

# Response Timeline

| Action | Expected Time |
|---------|---------------|
| Initial Response | Within 48 hours |
| Investigation | Within 7 days |
| Security Fix | As soon as possible |

---

# Scope

This policy covers:

- Authentication
- Authorization
- API Endpoints
- Database Security
- AI Services
- File Uploads
- User Data
- Environment Variables
- Third-party Integrations

---

# Security Best Practices

Please help us by:

- Using the latest version of Quantiva-AI
- Keeping dependencies updated
- Never committing secrets or API keys
- Enabling Multi-Factor Authentication (MFA)
- Using strong passwords
- Reporting suspicious activity responsibly

---

# Out of Scope

The following are generally not considered security vulnerabilities:

- UI or visual bugs
- Typographical errors
- Feature requests
- Performance improvements
- Missing best practices without a demonstrable security impact

---

# Disclosure Policy

Please do not publicly disclose vulnerabilities until we have investigated and released a fix.

Responsible disclosure helps protect all users.

---

# License

This security policy applies to all supported releases of Quantiva-AI.
